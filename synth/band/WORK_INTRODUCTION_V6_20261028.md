# 星群——基于高云FPGA的多模态电子乐队与交互演奏工作站

**英文名称：ORCHESTRA-138 / Starcluster**  
**项目版本：V6；简介更新日期：2026年10月28日**  
**主控平台：Tang Mega 138K Pro，高云GW5AST-138B FPGA**

> 本简介涵盖完整作品设计、当前板端实现、扩展软件和验证情况。当前已交付软件升级与原生板级可运行版本；包含外部DAC、实体面板和无线桥的完整整机仍需接线联调与物理验收。本文不把规划、源码、仿真或综合结果写成实物验收成绩。

## 一、作品概述

“星群”是一套以高云FPGA为实时音频核心，将电子乐器、自动乐队、实体交互、音乐编排、演奏事件录制与音频可视化结合的交互演奏工作站。作品围绕“能演、能编、能协作、能脱机、能验证”的目标展开，使使用者能够通过打击垫、旋钮、MIDI设备、电脑或手机参与演奏，并在人工演奏与自动伴奏之间切换。

系统采用事件驱动的参数合成方式。曲目以音符及控制事件保存，FPGA根据音高、力度、包络和音色参数实时计算声音，承担调度、发声、混音及对应配置中的硬件效果。电脑负责编辑、录制和展示，外部桥负责连接USB-MIDI或蓝牙控制设备；演奏音频不依赖电脑播放整曲录音。

作品建立了16个声部的控制体系和15个算法合成预设，覆盖弦鸣式、气鸣式、膜鸣、体鸣及电子、人声式音色；完整扩展另包含电子歌手、麦克风声码器、标准I²S音频、实体面板、板端事件回传、多曲ROM和LED指引。上位机提供音色库、16个屏幕打击垫、曲谱编排、混音、事件录制重放、场景管理及指标诊断，形成从演奏到创作、保存、重放和脱机工程导出的工作流程。

当前原生版本已经写入开发板SRAM和Flash，完成时序审查和真实板级数字回归。完整扩展具备源码、RTL测试和部分厂商综合证据，但尚不能作为全部外设已投入运行的整机成果。

## 二、设计目标与应用价值

作品主要面向以下需求：

1. **多音色实时演奏。** 用可调参数音源提供不同乐器的音色与奏法，支持力度、包络、弯音及表情等演奏控制。
2. **人工与机器协作。** 自动乐队维持曲目节拍和伴奏，演奏者可接管指定声部，再按小节归还，降低多人协作门槛。
3. **实体与软件结合。** 既能用上位机快速编排、调音和诊断，也为打击垫、脉冲旋钮、脚踏及手机提供接入路径。
4. **创作过程可保存。** 将演奏保存为可编辑、可重放的事件，而不是只能回听的整段音频。
5. **实时过程可观察。** 使用状态遥测和音频频谱展示声音生成、资源占用及交互过程，为教学和调试提供依据。
6. **可扩展、可复现。** 通过分离原生发布与扩展配置、保留构建脚本和证据，支持逐步完善实体产品。

适用场景包括音乐交互教学、FPGA数字信号处理实验、多人协作演奏、电子乐器原型开发以及创新设计竞赛展示。产品化和参赛达标仍需后续整机验收。

## 三、系统总体架构

系统由交互输入、事件控制、FPGA音频处理、音频输出、上位机及反馈显示六部分组成。

```text
电脑键盘 / MIDI输入 / 上位机编辑与录放 ── UART ──────┐
4×4 USB-MIDI垫 ── Teensy USB Host桥 ── UART ──────┤
手机控制页 ── BLE ── ESP32-C3桥 ── UART ───────────┤
本地压力采集 / 8路编码器 / 按钮 / 脚踏 ────────────┤
                                                  ↓
                     FPGA：事件校验、权限和声部接管
                                  ↓
                       音符调度 / 复音分配 / 曲目时基
                                  ↓
                 参数音源 / ADSR / 表情 / 混音 / 硬件效果
                                  ↓
       当前原生：PT8211右对齐输出   完整扩展：标准I²S→DAC
                                  ↓
                             模拟音频与监听

扩展I²S麦克风 → 捕获/声码器 → 电子歌手与音频混合
实际PCM → 加窗FFT/电平 → FPGA DVI显示；曲目事件 → LED指引
状态/健康计数/扩展已接受事件 → 上位机诊断与录制
```

上述图为完整系统设计。USB桥、BLE桥、模拟采集、麦克风和标准I²S部分属于扩展接入路径，尚未全部在当前板上物理连通。

电脑和桥接器处理界面或连接协议，FPGA保持实时发声核心地位。作品的名义主时钟为50MHz，音频事件和处理围绕48kHz采样时间组织；扩展音频设计采用24.576MHz音频基准，实际接口与时钟必须按最终配置审核。

## 四、核心演奏与声音功能

### 4.1 16声部与多角色乐队

系统组织为16个可寻址声部，容纳打击乐、贝斯、键盘和声、主奏、持续音、人声式合唱及扩展电子歌手。使用者可选择演奏席与目标声部，进行接管、静音和按小节归还。

多人控制采用来源、声部和音符实例身份，区分不同设备与同触点的多次按下。旧释放消息不能关闭新音符，旧会话授权不能直接作用于新会话。最后一个触点释放后可申请量化归还，再次演奏可取消待归还，以保持人工与自动乐队之间的衔接。

### 4.2 四类乐器与15个音色预设

| 类别 | 预设 | 主要用途 |
|---|---|---|
| 弦鸣式 | 明亮拨弦、弓弦式合奏 | 分解和弦、旋律及持续铺底 |
| 气鸣式 | 持续簧音、气息笛、管音风琴、强奏铜管 | 长音、旋律及表情控制 |
| 膜鸣 | 深沉底鼓、沙响军鼓 | 节奏和重音 |
| 体鸣/体鸣式 | 短促踩镲、金属钟、木琴 | 节拍、高频打击和短音旋律 |
| 电子 | 合成贝斯、FM电钢琴、柔和主奏 | 低音、和声及主旋律 |
| 人声式 | 元音合唱 | 合唱铺底和元音音色控制 |

以上合计15个预设。它们是参数合成与仿声音色，不宣称已经完成对应乐器的完整物理声学建模。第16声部的电子歌手是独立扩展角色，不额外冒称为第16个通用预设。

音色库支持选择、试听、ADSR编辑和用户预设保存/载入。原生版本通过选择算法声部应用音色；完整扩展支持声部与算法分离、逐轨声像及相应尾音处理，不能把两种配置的能力混为一谈。

### 4.3 包络、力度和表情

声音控制包含起音、衰减、持续和释放四阶段包络，并支持力度、表情、弯音及对应角色的元音参数。上位机提供参数编辑与场景保存，MIDI入口处理已支持的延音、弯音、通道/复音压力及控制变化，并按固件能力过滤不支持的消息。

对于电子歌手，音符、力度和表情等支持范围由固件声明；不能因其他声部支持ADSR或弯音，就推断歌手也支持相同参数。

### 4.4 复音与调度

当前整机使用256个音符槽的设计与遥测体系，并已经通过真实FPGA的256槽数字负载测试。事件调度围绕音频样本时基运行，音频路径与显示、编辑、通信等功能分离，提供期限违例、拒绝、削波和DAC丢样/欠载计数。

“256个活跃槽”表示经过验证的音符实例资源负载，不能直接写成“256个已测独立可闻音高”或“256个独立频谱峰”。后者需要额外的音频与频谱验收。

项目另保留独立加法分量池的规模探索：43008分量的固定节拍诊断RTL有仿真与谱峰证据。该结果仅属于隔离诊断实验，不是当前整乐队的实板复音能力，也不是芯片绝对性能上限。

### 4.5 混音与硬件效果

上位机提供逐轨音量、静音、独奏、主音量和效果旁路。完整扩展还包含逐轨声像以及延迟、多抽头混响、合唱等效果路径，参数可以随场景保存。

效果设计考虑饱和、反馈、尾音、清状态和忙时计数，避免错误状态影响实时音频。当前原生版本只开放其实际声明支持的能力，完整扩展效果不能一概记为当前板载效果均已验收。

### 4.6 电子歌手与麦克风

电子歌手路线包括有限元音/乐句编排、载波合成、麦克风捕获和16频带声码器。设计目标是让演奏音高与输入语音的频谱包络结合，形成具有语音特征的合成声音。

相关输入传输、滤波、混合、授权、表情和健康遥测具备软件或RTL验证。完整扩展可连接兼容I²S数字麦克风；当前原生板未接入真实麦克风，因此不能宣称实物声码器已验收。现阶段不提供任意自然语言歌词生成或完整自然人声演唱。

## 五、自动演奏、曲库与编排

作品包含96秒默认自动演奏曲目，围绕音符门控、音长和段落衔接优化连续性，保留有意休止和打击音头，并提供短间隙衔接工具。实际模拟输出的听感仍需监听验收。

编辑器提供1/16、1/32及三连音网格、音符移动与音长拖动、复制、撤销/重做、循环、节拍器和MIDI文件导入导出。内部以采样时间记录事件，网格只是编辑方式，不通过改变采样率解决音符间隔问题。

完整扩展内置三首事件曲目的ROM组织与选曲控制，并提供曲目状态和CRC/原子提交机制；上位机也可管理JSON曲库。ROM曲库通过工程重建后可随发布持久保存，运行时上传至RAM的曲谱断电不保留。

项目不依赖SD卡播放整曲音频，当前也没有实现SD/FAT大曲库文件系统。三曲板端ROM选曲能力属于扩展配置，当前原生固件的默认整曲运行证据不能替代该功能的实板验收。

## 六、实体面板与外部设备

### 6.1 4×4打击垫的两条路线

**USB-MIDI路线：** 使用已有16垫，通过Teensy 4.1的USB Host读取MIDI事件，再经UART交给FPGA。普通USB拓展坞不具备Host功能；需要时使用有源Hub改善供电。该路线不需要为USB垫另购FSR或ADC。

**自研压力路线：** 使用16个FSR等压力传感器，经模拟前端和MCP3208采集。16垫精简配置使用三片MCP3208：两片采16垫，第三片采8路连续控制。完整64垫/四席扩展架构保留，模拟采集配置为10片ADC，不能当作当前已经装配64垫。

USB垫能否提供持续压力由其实际MIDI消息决定；只有NoteOn力度的垫不能称为持续压力传感器。

### 6.2 八个脉冲旋钮

| 旋钮 | 对应功能 |
|---|---|
| 1 | 主音量 |
| 2 | 速度/BPM |
| 3 | 表情 |
| 4 | 参数编辑目标声部 |
| 5 | 起音 |
| 6 | 释放 |
| 7 | 效果量 |
| 8 | 合唱元音 |

旋钮采用增量式正交编码器，A/B信号由FPGA同步、去抖及方向解码，不需要ADC。线性电位器、模拟表达踏板或FSR才需要模拟采集。Teensy通过MIDI CC20选择USB演奏声部，与FPGA旋钮的参数编辑目标目前独立，不能宣传为自动同步。

### 6.3 脚踏与MIDI

本地踏板逻辑用于接管/归还；MIDI CC64及Teensy可选常开脚踏用于延音，两种语义分开。Teensy的MIDI延音与实体延音按逻辑或组合，处理零力度NoteOn、CC120/123释放和USB拔出后的来源回收。

模拟表达踏板或摇杆不是数字开关的无条件替代品，若使用需另外定义ADC、阈值和参数映射；当前不将其列为已完成实体功能。

### 6.4 ESP32-C3手机桥

ESP32-C3 SuperMini作为BLE GATT与UART之间的事件桥。手机页提供16垫、力度/表情/弯音/合唱元音、板载曲目的开始/停止及事件录音导出。手机席位可停止曲目；紧急panic、上传和管理权限按协议保留给电脑。

C3侧UART为1Mbaud、3.3V TTL，GPIO4/TX接FPGA RX，GPIO5/RX接FPGA TX，共地。该桥不传演奏音频，也不具备替代Teensy的USB Host能力。

手机网页面向支持Web Bluetooth的Android Chromium及桌面Chromium，并要求HTTPS或localhost环境；iPhone Safari不支持该页面依赖的接口。桥固件编译与软件行为验证已完成，真实手机配对、射频和浏览器兼容性尚待测试。

### 6.5 Teensy USB桥

Teensy 4.1通过USB Host连接兼容USB-MIDI的垫，Serial1 pin 1/TX接FPGA RX，pin 0/RX接FPGA TX，共地、1Mbaud；GPIO2对地可接选配常开延音脚踏。固件具备来源释放、租约、断链和重连身份查询，并已编译、执行实际C++回调的模拟IO测试。尚未在用户真实垫和Teensy上完成刷写与枚举验收。

### 6.6 三种扩展导出配置

| 配置 | 适用场景 | 特点 |
|---|---|---|
| 完整扩展 | 完整面板与多输入研究 | 保留64垫/四席、10ADC及完整音频/显示功能的扩展源码 |
| 16垫精简扩展 | 自研16个压力垫 | 三片ADC，16压力通道与8连续控制通道；保留数字编码器 |
| USB16垫无ADC扩展 | 复用现有USB垫 | 去除模拟采集端口及模拟前端，保留编码器、数字按钮和桥接接口 |

工程导出保存逐轨算法、包络、声像、混音、效果、校准和曲库；默认停止，不覆盖已有目录。旧格式无法保留高级参数时明确拒绝，避免静默丢失。没有审核的扩展CST/SDC时拒绝布局布线，不能将未知引脚扩展直接烧到板上。

## 七、音频输出、显示与视觉实验

当前板端采用开发板PT8211及其右对齐串行输出，具备DVI显示、UART和三个板载按钮的固定引脚封装。PT8211当前接口不作为标准I²S达标证明。

完整扩展提供标准I²S发送/接收、队列、跨时钟传输、时钟丢失静音、麦克风接入及DAC顶层。目标外置DAC可选兼容3.3V逻辑的PCM5102A模块，音频设计采用24.576MHz基准；必须核实真实时钟输入脚、接口约束、电平和实际模块配置后接线。数字MEMS麦克风可选择适配的I²S模块，不能把USB/PDM麦克风直接当作同一接口。

音频可视化包含实际PCM分析、Hann加窗、2048点FFT及频谱条显示。频谱链分析左声道，保留左右峰值信息，不宣传为双声道合并频谱或已经标定的声压计。DVI视频经板上相应连接器输出，不据此宣称完整HDMI音频功能。显示下游拥塞时可丢弃可视化窗口并计数，避免反向阻塞声音路径。

扩展LED方案包含12个音高类别灯和1个节拍灯，依据曲目事件给出音高/节拍指引，目标是脱离电脑后的辅助演奏。真实屏幕与LED面板仍需验收。

项目另有实验性视觉选择界面：通过本地摄像头寻找单个红色标记，停留后确认选择后续演奏角色，音符仍由键盘或MIDI输入。它是颜色标记选择，不是通用人体/手势识别；已有合成图像和控制逻辑证据，真实摄像头、光照、误触和RK3588部署尚未验收。

## 八、上位机与创作工作流

上位机采用Python与PySide6实现，主要界面包括主演奏台、工作站、曲谱编辑、舞台状态和实验视觉入口。

| 功能区域 | 包含内容 |
|---|---|
| 主演奏台 | 串口识别、构建ID/能力查询、演奏席、MIDI连接、声部接管/归还/静音、键盘演奏、开始/停止及总停音 |
| 音色库 | 四类/15预设、分类筛选、试听、ADSR、用户预设、16个屏幕垫及力度设置 |
| 事件录制/重放 | 开始/结束录制、保存/载入、重放、变速与循环、完整性提示 |
| 混音/控制 | 轨道音量、静音/独奏、效果旁路及按固件能力开放的声像和效果模式 |
| 曲库/场景 | JSON曲库、扩展板端曲目选择/状态、场景保存恢复、曲谱上传与脱机工程导出 |
| 编辑器 | 细网格、音符与音长编辑、撤销重做、循环/节拍器、MIDI导入导出 |
| 舞台状态 | 所有权、机器/人工状态、活跃槽和独立歌手状态、健康计数与可追溯遥测 |
| 赛项/诊断 | O01–O10逐项要求、实现能力、证据、缺口和诊断导出 |
| 压力校准 | 扩展压力前端的阈值/校准参数配置和工程导出 |

上位机会按板端能力限制功能。外部已接受的控制可同步界面和保存场景，避免回发形成循环；串口断开清除旧授权、半次上传和录制缓存。没有连接或能力不符时不伪装成功。

典型工作流为：连接与核对固件→选择席位/声部→应用预设与调音→现场或自动演奏→录制事件→保存与重放→编辑曲谱/场景→上传或导出脱机工程→观察遥测与诊断。

## 九、事件录音与重放

用户本轮选择的是演奏事件录制。记录内容包含音符、力度、释放、控制动作、相对时间和初始场景；重放根据事件重新合成声音，不是回放WAV。

软件处理录制开始时已经观察到的保持音符，以及结束时尚未释放的音符。重放重新申请声部授权、使用新音符实例身份，不复用旧epoch/serial；循环、停止和现场输入冲突按规则处理。

完整扩展通过“板端已接受事件”回传与样本时间戳覆盖本地垫和旋钮动作。回传丢失会标记录制不完整并停止相应过程，不能当成完整演出静默重放。软件不能回溯连接前的硬件状态，真实本地动作的录放仍需扩展实板验证。

手机页面的事件导出和上位机整机录制具有各自覆盖范围，不等同于任意来源的音频录制。

## 十、异常处理与工程可靠性

系统使用事件身份、来源权限、心跳/租约、断链释放、CRC、上传校验及总停音机制。显示、参数通信或文件操作不应阻塞音频，异常队列与处理期限通过计数暴露。

恢复设计包括：旧释放保护、上传失败不静默提交、重连清旧状态、丢钟停音、时钟恢复不自动续播旧音符，以及录制完整性检查。安全启动、模拟输出爆音、真实电源故障和长期温升必须通过实际硬件测试，不能仅以代码存在宣称通过。

发布流程为：源码与约束冻结→综合/PnR与时序/引脚审查→SRAM加载→真实数字回归→Flash厂商校验→重载身份确认→选择器切换。旧发布保留供回退，失败日志保留，不将失败记录删去后报告一次成功。

供电与通信单独成图。FPGA使用板卡规定电源，桥可各自USB供电并共地；不把多个USB 5V输出并联，不用FPGA IO给大电流外设供电。扩展引脚尚未冻结时，不凭相似板图猜测实体管脚。

## 十一、设计特点与可论证的创新点

1. **FPGA实时音频与多角色协作结合。** 将发声、节拍、资源调度和声部所有权组织到同一事件系统，支持自动伴奏与人工接管共存。
2. **多模态输入共享音符身份。** 将键盘、MIDI、本地面板及手机控制映射到受权限保护的来源与声部，避免多输入下的误释放和旧会话干扰。
3. **演奏过程可编辑、可重建。** 录制音符与控制动作，结合初始场景及新授权重放，使作品可继续调整音色、速度和编排。
4. **面向实际器件的配置裁剪。** 同时提供完整扩展、三ADC的16垫方案和USB无ADC方案，减少不需要的模拟前端和采购。
5. **音频与可视化解耦。** 从实际PCM提取频谱，给显示独立背压和丢窗计数，避免显示拥塞影响声音。
6. **能力与证据一致。** 界面按固件能力开放功能，分开记录源码、仿真、综合、时序、板级数字及实物测量，增强作品的可复现性。

这些是本作品的设计特点和待答辩论证方向，不代表已经完成新颖性检索或全部实物验证；第三方移植代码按许可与来源说明保留署名。
